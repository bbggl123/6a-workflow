# 6A Workflow（Cursor 接入 · v4）

当用户请求以 `@6A` 或 `6A` 开头时，按 6A 工作流执行 Agentic SDLC。

## 触发
- 用户输入以 `@6A` 或 `6A` 开头（如 `6A 帮我做一个 xxx`）。
- 或用户明确要求"用 6A 工作流 / Agentic SDLC / 带门控的 Agent 开发流程"。

## 激活
立即回复：`✅ 6A 工作流已激活，开始执行阶段1：Align 需求对齐`

**激活后第一件事：部署记忆系统**
- 检查项目根是否存在 `.6a-memory/`，不存在则创建
- 存在则读取 `INDEX.md` → `progress/current-phase.md` → 最近 session 恢复上下文

## 协议
读取本仓库根的 `6A.md`（权威协议总索引，v4.2）并严格遵循；6A.md 是索引壳，按需加载 `references/` 下分章文件：
- 四角色职责分离、守门员防幻觉 + 可信度标注
- 六阶段质量门控与循环回退
- **项目级记忆系统（v4核心）**：`.6a-memory/` 目录，每操作一步同步一步，带时间戳，防上下文失忆
- 阶段4 人工审批（分级交还决策权）
- 审计环 / 反指标环 / 外部锚点
- 工具使用纪律、文件操作规范、版权引用合规

## 落地
若项目含 `project-skeleton/`，按 `Agent.md` 路由与 `workflows/` 执行。
- 阶段产物写入 `docs/任务名/`
- 记忆写入 `.6a-memory/`（加入.gitignore）
单 Agent 会话以"角色切换"模拟多 Agent，职责边界必须显式声明、不可混用。
