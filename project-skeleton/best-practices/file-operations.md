# 文件操作纪律（File Operations）

> 来源：Claude Opus 5 文件三层分离思想 + 6A 工程规范

## 目录职责分离

| 目录类型 | 路径约定 | 权限 | 说明 |
|---|---|---|---|
| **只读输入区** | 用户上传文件、`node_modules/`、`.git/`、系统目录 | 只读 | 仅读取分析，禁止修改；需改时先复制到工作区 |
| **工作区** | 项目源码根目录、`/data/user/work/`（临时） | 读写 | 代码修改、文档编写、临时脚本 |
| **交付输出区** | `/workspace/`（最终交付）、`docs/任务名/`（阶段产物） | 读写 | 最终给用户的文件，必须完整、干净、可访问 |

## 文件创建规则

### 新建前检查
1. **检查文件是否存在**：同名文件存在时不要直接覆盖
2. **判断是更新还是新建**：修改已有功能优先编辑现有文件，而非新建
3. **确认路径正确**：使用绝对路径，避免工作目录变化导致文件写错位置
4. **确认目录存在**：写入文件前确保父目录存在

### 文件命名
- 使用有意义的文件名，见名知意
- 遵循项目现有命名风格（kebab-case / snake_case / CamelCase）
- 临时文件加 `.tmp` 或明确标注"临时"，任务结束清理

### 编码与格式
- 所有文本文件使用 **UTF-8** 编码
- 换行符使用 **LF**（Unix风格），不用 CRLF
- 文件末尾保留一个空行（POSIX惯例）
- 删除 trailing whitespace（行尾空格）

## 文件编辑规则

### 编辑前
- **必须先读取文件最新内容**（这是铁律）
- 理解代码/文档上下文，不要断章取义
- 确定修改范围，避免不必要的改动（最小修改原则）

### 编辑中
- 大文件（>500行）分段读取、分段修改，每次只改相关区域
- 使用精确的字符串替换（old_str 必须唯一匹配）
- 保持原有代码风格、缩进、命名约定一致
- 关键逻辑添加注释（中文）

### 编辑后
- 立即读取修改区域，确认改动正确
- 代码修改后运行语法检查/测试
- 更新相关文档（接口变更更新接口文档）
- 在记忆系统记录 `[MODIFY]`

## 文件交付规则

### 交付物要求
- 最终交付文件放在 `/workspace/` 目录下
- 文件内容完整、格式正确、无调试残留
- 无敏感信息（API Key、密码、个人隐私）
- 代码可运行、文档可阅读

### 文件链接
- 给用户的文件链接使用格式：`[文件名](computer:///workspace/路径)`
- 多文件交付时给出文件清单和每个文件的用途说明
- 链接使用相对用户的表述，不暴露内部绝对路径

### 临时文件清理
- 调试用临时脚本、中间输出文件，任务结束前清理
- 除非用户要求保留，否则不留下垃圾文件
- `.6a-memory/` 目录保留（供续接任务使用），但加入 `.gitignore`

## .gitignore 规范

项目必须包含 `.gitignore`，至少排除：
```
# 依赖
node_modules/
__pycache__/
*.pyc
venv/

# 构建产物
dist/
build/
*.log

# 环境变量
.env
.env.local

# IDE
.vscode/
.idea/

# 6A 记忆系统（本地工作记忆，不入库）
.6a-memory/

# 临时文件
*.tmp
*.bak
```

## 反模式（禁止）
- ❌ 不读文件直接凭记忆编辑
- ❌ 直接覆盖已有文件而不先读内容
- ❌ 使用相对路径导致文件写到错误位置
- ❌ 大文件整篇重写而非局部修改
- ❌ 编辑后不验证直接继续
- ❌ 交付文件包含敏感信息或调试代码
- ❌ 临时文件不清理污染项目目录
