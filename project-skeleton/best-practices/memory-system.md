# 记忆系统使用手册（Memory System）

> v4 核心新增：项目级持久化记忆，解决长任务上下文失忆问题

## 为什么需要记忆系统

LLM 上下文窗口有限，长任务中常见"失忆"症状：
- 忘记之前做过什么决策
- 重复读取已经读过的文件
- 忘记用户已经确认过的事情
- 中断后续接时不知道从哪开始
- 关键约定和约束在对话变长后丢失

记忆系统通过**"每操作一步同步一步"**的持久化日志，让 AI 在任何时候都能从磁盘恢复完整上下文，而不依赖对话历史。

## 部署时机

**6A 激活后第一件事（阶段1步骤0）**就是部署记忆系统：

```bash
# 检查是否已存在
if [ -d ".6a-memory" ]; then
  echo "记忆系统已存在，恢复上下文..."
else
  echo "部署新的记忆系统..."
  mkdir -p .6a-memory/{session,context,decisions,progress,lessons}
fi
```

### 续接任务
如果 `.6a-memory/` 已存在，说明是中断后续接，必须按顺序读取：
1. `.6a-memory/INDEX.md` - 总览
2. `.6a-memory/progress/current-phase.md` - 当前进度
3. `.6a-memory/session/` 下最新的会话日志 - 最近发生了什么
4. `.6a-memory/decisions/` 按编号倒序读最近5条决策

## 目录结构详解

```
.6a-memory/
├─ INDEX.md                 # 记忆总索引（每次操作更新）
├─ session/                 # 会话日志（追加式，只增不改）
│   └─ 2026-07-27-034500.md # 启动时间命名的会话文件
├─ context/                 # 项目画像（可更新）
│   ├── project.md          # 技术栈、架构、目录结构、命名规范
│   ├── codebase.md         # 关键文件、核心模块、已有组件、依赖
│   └── domain.md           # 业务领域、数据模型、术语表
├─ decisions/               # 决策日志（不可变，每个决策一个文件）
│   └─ DECS-001.md ~ DECS-NNN.md
├─ progress/                # 任务进度（实时更新）
│   ├── current-phase.md    # 当前阶段、角色、正在做的任务
│   ├── completed.md        # 已完成任务清单+验收证据
│   └── blockers.md         # 阻塞项、待用户确认的问题
└─ lessons/                 # 经验教训
    └─ learned.md           # 本次任务的坑、有效技巧
```

## 记忆条目格式

每条记忆必须使用统一模板，写入对应文件：

```markdown
### [动作类型] 简短摘要
- **时间**: `2026-07-27 03:45:00 (UTC+8)`
- **阶段**: Align / Architect / Atomize / Approve / Automate / Assess
- **角色**: 规划 / 执行 / 评估 / 守门员
- **相关文件**: `path/to/file1`, `path/to/file2`
- **详情**:
  （具体做了什么、发现了什么、决定了什么）
- **可信度**: XX%（涉及结论/决策时必填）
```

### 动作类型枚举

| 类型 | 触发时机 |
|---|---|
| `[READ]` | 读取了重要文件/资料 |
| `[DECIDE]` | 做出了设计/选型决策 |
| `[MODIFY]` | 修改/创建了文件 |
| `[RUN]` | 运行了命令（测试/构建/脚本） |
| `[FIND]` | 发现了问题/关键事实 |
| `[ASK]` | 向用户提出了问题 |
| `[APPROVE]` | 用户确认/审批了事项 |
| `[ERROR]` | 遇到了错误/阻塞 |
| `[CHECKPOINT]` | 阶段完成/门控通过/任务开始结束 |

## "每步同步"执行纪律

### Write-ahead Memory Logging（先写再做）

关键动作**之前或立即之后**写记忆，不要等：

| 动作 | 记忆操作 |
|---|---|
| 读取重要文件 | 立即在 session 记录 `[READ]`，摘要文件核心内容 |
| 做出决策 | 在 decisions/ 创建 DECS 条目，session 记录 `[DECIDE]` |
| 修改/创建文件 | 记录 `[MODIFY]`，说明改了什么 |
| 运行命令 | 记录 `[RUN]`，记录命令和关键结果 |
| 遇到错误 | 立即记录 `[ERROR]`，记录现象和初步判断 |
| 用户确认 | 记录 `[APPROVE]`，记录确认内容 |
| 阶段切换 | 记录 `[CHECKPOINT]`，更新 current-phase.md |
| 任务开始/结束 | 记录 `[CHECKPOINT]`，更新 completed.md |

### 上下文恢复规则

当你感觉"不确定之前做了什么"时：
1. **不要猜**，不要假设
2. 先读 `progress/current-phase.md`
3. 再读最近 session 日志（最近10-20条记录）
4. 需要决策细节时读对应 DECS 文件
5. 代码修改前，查 `context/codebase.md` 是否已有该模块记录，避免重复读取

### 记忆完整性自检（守门员职责）

每个阶段质量门控必须检查：
- 该阶段的关键操作是否都有对应记忆记录
- session 日志时间戳是否连续（超过10分钟间隙需提醒补记）
- 决策是否都记录到了 decisions/
- 进度文件是否实时更新

## 决策文件（DECS-NNN.md）模板

每个关键决策单独一个文件，便于追溯：

```markdown
# DECS-001: 决策标题

- **时间**: `2026-07-27 04:00:00 (UTC+8)`
- **阶段**: Architect
- **决策内容**:
  （具体决定了什么）
- **备选方案**:
  - 方案A：...（为什么没选）
  - 方案B：...（为什么选了这个）
- **依据**:
  （做出这个决策的理由）
- **可信度**: XX%
- **相关文件**: `path/to/file`
```

## current-phase.md 模板

```markdown
# 当前进度

- **启动时间**: `2026-07-27 03:45:00`
- **当前阶段**: Align / Architect / Atomize / Approve / Automate / Assess
- **当前角色**: 规划 / 执行 / 评估 / 守门员
- **正在做**: T03 - 实现用户认证模块
- **最近完成**: T02 - 数据库设计
- **下一步**: 等待用户审批设计方案
- **最后更新**: `2026-07-27 04:30:00`
```

## 隐私与安全

- `.6a-memory/` 默认加入 `.gitignore`（本地工作记忆，不提交到Git）
- **禁止记录**：API密钥、密码、个人隐私数据
- 敏感信息用 `[REDACTED]` 占位
- 任务结束后，`lessons/learned.md` 中可复用的经验沉淀到项目 `knowledge/` 目录（持久化保留）
- session 和 decisions 保留在本地，供续接使用

## 常见问题

**Q: 会不会增加很多额外工作量？**
A: 每条记忆只有几行，写一条记忆几秒钟，但能节省大量重复读取和反复确认的时间。习惯后是条件反射。

**Q: 记忆文件会不会越来越大？**
A: session 日志按会话分文件（每次启动一个新文件），不会无限增长；context 和 progress 是更新式而非追加式；decisions 一个决策一个文件，不会重复。

**Q: 我需要手动创建这些文件吗？**
A: 6A 激活时会自动初始化目录结构；之后的记忆条目由 AI 在执行过程中自动写入，不需要用户手动操作。

**Q: 可以人工编辑记忆文件吗？**
A: 可以。记忆是纯文本 Markdown，用户可以随时查看、修正、补充。这也是可审计性的一部分。
