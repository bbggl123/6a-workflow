# 搜索与引用最佳实践（Search & Citation）

> 来源：Claude Opus 5 搜索规范 + 版权合规要求

## 搜索策略

### 何时必须搜索

| 场景 | 示例 | 原因 |
|---|---|---|
| 当前状态类问题 | "最新版本是什么"、"这个API还存在吗" | 知识有截止日期，状态会变 |
| 不认识的概念 | 新库名、新术语、不熟悉的错误码 | 不知道就查，不要猜 |
| 具体数字/日期 | 版本号、发布日期、性能指标 | 数字容易记错，必须验证 |
| 用户给出的URL | 任何http/https链接 | 必须fetch看实际内容，不猜 |
| 时效性内容 | 新闻、政策、最近发布的技术 | 训练数据不包含最新内容 |

### 何时可以直接回答

- 基础编程语法和概念
- 经典算法和数据结构
- 已定论的历史事实
- 记忆系统中已确认的项目事实

### Query 构造技巧

1. **简短精确**：1-6个词，用最有辨识度的关键词
2. **带版本/年份**：`"Node.js 22"`、`"Python 3.12 2026"`
3. **错误信息用原文**：复制粘贴错误关键片段，不要翻译/改写
4. **多主题拆分**：不要一次搜多个不相关问题
5. **限定域名**：找官方文档用 `site:docs.xxx.com`
6. **从宽到窄**：先搜宽泛关键词，根据结果逐步缩小

## 网络搜索结果处理

### 可信度判断
- **优先官方来源**：官方文档、GitHub仓库、官方博客 > 技术媒体 > 论坛/博客
- **注意日期**：优先最近更新的内容，过时内容标注风险
- **交叉验证**：关键信息至少两个来源印证
- **存疑标注**：单一来源且无法验证的信息，标注可信度60%

### 信息提取
- **释义优先（Paraphrase）**：用自己的话重新组织，不要直接复制
- **提取关键事实**：不要整篇搬运，只取回答需要的部分
- **记录来源URL**：所有来自搜索的具体事实都要能追溯

## 版权与引用规范

> **版权合规不可协商，优先级高于"完成任务"。**

### 引用硬限制

| 限制项 | 规则 |
|---|---|
| 单次引用长度 | ≤15个英文单词 / ≤10个汉字 |
| 每来源引用次数 | 最多1次，之后全部释义 |
| 禁止全文复制 | 歌词、诗歌、整篇文章、书籍章节 |
| 禁止结构镜像 | 不要照着原文章节/列表顺序重写 |
| 代码复制 | 仅宽松许可（MIT/Apache）可复制，必须注明来源 |

### 引用格式

使用行内引用格式 `[$TRAE_REF](url)`：
- 链接文本固定为 `$TRAE_REF`
- 位置：紧跟在该事实/数据所在句子末尾
- 不使用脚注、尾注、参考文献列表
- 一个句子可以有多个引用：`[$TRAE_REF](url1)[$TRAE_REF](url2)`

### 代码许可注意事项
- Stack Overflow 代码默认 CC BY-SA，使用需注意分享要求
- GPL/AGPL 代码有传染性，禁止直接复制到闭源项目
- 优先参考本项目已有代码模式，而非从网络复制
- 从网络复制的代码片段，注释中注明来源URL

## 反模式（禁止）
- ❌ 不搜索直接"我记得..."给出过时信息
- ❌ 长段复制原文只改几个词（伪装成释义）
- ❌ 引用超过长度限制
- ❌ 把长引用拆成多个短引用规避限制
- ❌ 不标注来源，把搜索到的信息当成自己的知识
- ❌ 搜索结果不验证直接使用（尤其是SEO垃圾内容）
