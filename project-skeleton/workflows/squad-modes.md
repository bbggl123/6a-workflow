# 智能小队协作模式 —— 可复用操作协议（v4.4 新增）

> 本文件是 6A 第十章（`references/6A-squad.md`）的配套操作手册，定义 8 种协作模式的可复用 prompt 模板、派发规则与收口标准。
> 队长（主 Agent / 规划 Agent）在阶段3 Atomize 后按决策树选择模式，在阶段5 Automate 前按本文件派发。

---

## 模式选择决策树（快速版）

```
单一专家可独立完成？ → ① 路由
有串行依赖？         → ⑥ 接力
需多视角回答同一问题？
  需选最优解？       → ⑤ 投票
  有实质分歧需辩论？ → ③ 圆桌讨论
  否则               → ② 专家会诊
可拆独立并行子任务？ → ④ 并行
需产出→评审→迭代？   → ⑦ 生产评审
需对抗性辩论？       → ⑧ 红蓝对抗
无匹配               → 队长直接处理
```

---

## ① 路由模式

### 派发模板（单专家）

```
你是 {专家角色}，请处理以下任务：

任务：{任务描述}
输入契约：{输入}
输出契约：{输出}
验收标准：{验收标准}
Constitution 约束：{已加载的 CONSTITUTION.md 摘要}

请就地处理并直接交付，交付后自己结束任务，无需回传队长。
交付物须附可信度四行标注。
```

### 派发模板（多专家，各自独立任务）

```
以下任务需要分派给不同领域专家，各自独立完成后回传队长汇总：

- @{专家A}：处理 {任务A描述}
- @{专家B}：处理 {任务B描述}

各自交付后回传，由队长汇总收口。
```

### 收口规则
- 单专家：其交付即最终答案，队长不复述不总结。
- 多专家：队长汇总去重，校验接口一致性。

## ② 专家会诊模式

### 派发模板

```
以下问题需要从多个专业角度独立分析。各子任务相互独立、互不可见。

问题：{问题描述}

并行子任务：
- 子任务 → @{专家A}：从 {角度A} 分析
  输出：{角度A 的分析框架与结论}
- 子任务 → @{专家B}：从 {角度B} 分析
  输出：{角度B 的分析框架与结论}
- 子任务 → @{专家C}：从 {角度C} 分析
  输出：{角度C 的分析框架与结论}

各方独立作答，完成后回传队长整合。
```

### 整合模板（队长）

```
各方分析已收集，整合如下：

【共识点】{各方一致认同的结论}
【分歧点】{各方不一致的判断，附各方依据}
【整合结论】{队长综合各方意见的统一结论}
【保留意见】{未被采纳的视角，标注原因}
```

## ③ 圆桌讨论模式

### 开场模板（队长）

```
【圆桌议题】{原样议题}

【交付要求】
- 要回答：{核心问题}
- 要带依据：{数据/案例/引用}
- 篇幅：{字数限制}

请以下成员按此顺序接龙发言：
@{成员A} @{成员B} @{成员C}

轮到时自行选择角度切入，给出独立判断。
可以回应他人、提新角度、被说服后改立场。
不必逐条对答，但须正面回应针对你的追问。
```

### 追问模板（队长，每轮后）

```
本轮讨论总结：
【共识】{已达成的共识}
【分歧】{仍存在的分歧}
【薄弱点】{证据不足或视角缺失处}

就以下薄弱点追问：
- @{成员X}：你的 {论点} 缺乏 {依据类型}，请补充或修正。
- @{成员Y}：{视角Z} 似乎未被覆盖，请从该角度补充。
```

### 收口模板（队长）

```
圆桌讨论收口。

【最终结论】{收敛后的结论}
【结论如何达成】{哪些质疑修正了初始判断}
【保留意见】{未收敛的分歧与持方}
【依据汇总】{关键论据清单}
```

## ④ 并行模式

### 派发模板

```
任务已拆成以下相互独立的并行子任务，彼此无依赖：

- 子任务 → @{成员A}：{任务A}
  输入：{A的输入}  输出：{A的输出}  验收：{A的验收标准}
- 子任务 → @{成员B}：{任务B}
  输入：{B的输入}  输出：{B的输出}  验收：{B的验收标准}
- 子任务 → @{成员C}：{任务C}
  输入：{C的输入}  输出：{C的输出}  验收：{C的验收标准}

各自独立执行，完成后回传队长合并。
```

### 合并模板（队长）

```
各子任务已完成，合并如下：

【去重】{重复内容合并}
【合并结果】{统一交付物}
【一致性校验】{接口/命名/依赖校验结果}
```

## ⑤ 投票模式

### 派发模板

```
以下问题需要多个独立解，从中择优。各方隔离作答，互不可见。

问题：{问题描述}
约束：{技术约束/性能要求/验收标准}

- @{成员A}：给出你的方案（含核心思路、实现要点、优劣势分析）
- @{成员B}：给出你的方案（同上）
- @{成员C}：给出你的方案（同上）

各自独立作答，完成后由队长收集择优。
```

### 择优模板（队长）

```
三方方案已收集，择优如下：

【评判标准】{列出评判维度与权重}
【方案对比】
| 维度 | 方案A | 方案B | 方案C |
|---|---|---|---|
| {维度1} | ... | ... | ... |

【最优方案】{选择结果}
【选择依据】{为什么选这个}
【备选方案】{落选方案保留，标注差异点}
```

## ⑥ 接力模式

### 派发模板

```
任务已按串行依赖拆成接力棒次，用依赖链串联：

棒1 → @{成员1}：完成 {步骤1描述}
  输入：{初始输入}  输出：{中间产物1}
棒2（依赖棒1）→ @{成员2}：基于棒1产物完成 {步骤2描述}
  输入：{中间产物1}  输出：{中间产物2}
棒3（依赖棒2）→ @{成员3}：完成 {步骤3描述} 并交付
  输入：{中间产物2}  输出：{最终交付物}

每棒完成后自动解阻塞下一棒。上游产物不达标不交付下游。
全部完成后队长汇总。
```

### 交接校验（每棒完成时）

```
棒{N}已完成，交接校验：
- 上游产物完整性：{校验结果}
- 下游输入契约匹配：{校验结果}
- 可解阻塞棒{N+1}：是/否
```

## ⑦ 生产评审模式

### 生产者派发模板

```
你是生产者，请产出以下交付物的初稿：

任务：{任务描述}
输出契约：{交付物组成/格式/质量标准}
Constitution 约束：{摘要}

产出初稿后 @{评审者} 请其评审。
```

### 评审者模板

```
你是评审者，请对以下初稿给出明确结论：

初稿：{生产者的产出}
验收标准：{验收清单}

你的结论必须是以下之一：
- 通过 → @{生产者} 可以交付
- 不通过 → 列出具体意见（精确到问题点）

不得模糊放行。「能用但不专业」= 不通过。
```

### 循环控制
- 最多 3 轮修改→复审。
- 超 3 轮：队长兜底，直接介入修改或换人。

## ⑧ 红蓝对抗模式

### 开场模板（队长）

```
【辩题】{辩论议题}
【红方立场】{红方主张}
【蓝方立场】{蓝方主张}
【先后次序】红方先立论

@{红方} @{蓝方}

规则：
1. 红方先发布完整主张（核心判断+论据+边界），发布后 @ 蓝方。
2. 蓝方先发布完整主张，再逐条挑战红方已发布的主张，然后 @ 红方。
3. 被挑战方须正面回应：接受修正或拿出更强依据反驳。
4. 双方直接互相 @ 接力，不经过队长中转。
5. 不再出现新的有效反驳时，任一方 @ 队长请求收口。
6. 交锋最多 3 个回合，超出队长直接介入。

队长不下场任一方，只在最后作为裁判收口。
```

### 收口模板（队长裁判）

```
红蓝对抗收口。

【裁判结论】{权衡双方论据后的结论}
【结论如何达成】{哪些攻防修正了裁判最初的判断}
【未回应的挑战】{点名要求补回应的项}
【保留意见】{若拍板，注明保留意见}
```

## 与 Gauntlet Loop 的关系

Gauntlet Loop（`workflows/gauntlet-loop.md`）= ④ 并行模式 + ⑦ 生产评审模式的组合特例：
- 并行执行（模式④）+ 评委盲测验收（模式⑦变体）+ 循环打回。
- complex 任务仍推荐直接用 Gauntlet Loop（它已内建完整的循环控制与验收清单）。
- 本章的 8 种模式是通用框架，Gauntlet Loop 是预设组合，两者互补不冲突。
