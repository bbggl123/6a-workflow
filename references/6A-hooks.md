# 生命周期 Hook（v4.2 新增 · v4.3 增 on-task-complete）

> 本文件是 6A 权威协议的分章加载单元。理解阶段切换与自动动作触发时加载；脚本化版本见 `project-skeleton/hooks/`。

> 课程原则：Hook 在开始、完成、失败等节点**自动触发固定动作**（如代码审查完发通知），不依赖模型每步自觉执行。6A 定义五类触发点：

| Hook | 触发时机 | 固定动作 | 降级（平台不支持 Hook） |
|---|---|---|---|
| `on-phase-enter` | 进入某阶段时 | 写记忆 `[CHECKPOINT] 进入阶段X` + 更新 `progress/current-phase.md` | 模型显式执行（不静默跳过），阶段开头第一句即写 |
| `on-phase-exit` | 阶段质量门控通过时 | 写 `[CHECKPOINT] 阶段X 完成` + 更新 `completed.md` + 通知（如发评论/消息） | 模型显式执行 + 主动向用户同步阶段完成 |
| `on-gate-fail` | 门控不过时 | 记录失败原因到 `blockers.md` + 记录 `[ERROR]` + 循环回退起点 | 模型显式记录原因后再回退，不得静默重做 |
| `on-irreversible-action` | 删除 / 迁移 / 部署 / 强推前 | 要求人工确认（与阶段4 三级制联动）+ 记录 `[APPROVE]` | 模型显式停下向用户确认，确认后才执行 |
| `on-task-complete`（v4.3 新增） | 阶段5 单个原子任务 Txx 标记完成时 | ⑴ 校验实质产出 vs TASK 契约（文件改动/测试/验证结果是否存在）；⑵ progress/ 勾选 `[ ]`→`[x]` 并刷新任务清单状态；⑶ 检测「制造干活的假象」——留痕密集但无实质产出 → 判不通过、打回重做；⑷ 若该任务是后续「可并行」任务的前置 → 提醒主 Agent 派发后续任务 | 模型显式执行四步动作，不得仅凭 `[CHECKPOINT] 任务完成` 就放行 |

## on-task-complete 详解（v4.3 新增 · 任务粒度检查点）

> v4.2 的 `on-phase-exit` 是**阶段粒度**门控——整个阶段5 通过时才触发。但阶段5 内部有多个原子任务，单任务「假完成」（留痕密集但无实质产出）能在阶段门控前混过去。Spec Kit implement 命令强调「review 小改动不看巨型 diff」——任务粒度需要独立检查点。`on-task-complete` 补上这一层。

**「制造干活的假象」检测规则**（脚本化判定，见 `project-skeleton/hooks/on-task-complete.sh`）：
- 该任务 Txx 的 session 留痕条数 ≥3，但 `git diff` 无对应文件改动 → 假象
- 该任务 Txx 声称「测试通过」，但无新增/修改测试文件或无 `[RUN]` 结果 → 假象
- 该任务 Txx 声称「完成」，但 TASK 契约约定的交付物文件不存在 → 假象

命中任一 → `on-gate-fail` 联动，打回该任务重做（最多 3 轮，连续失败交人工）。

**与并行标注联动**：当 Txx 完成且 TASK 清单中存在标「依赖前置 [Txx]」的后续任务，本 Hook 提醒主 Agent 派发这些后续任务（标「可并行」的可同时派发）——防止「并行需人工催」被遗忘（Gotchas #12）。

## 实现形态

1. **平台原生 Hook**：若运行平台支持生命周期回调，优先用平台 Hook 注册上述五类触发点的固定动作。
2. **脚本化降级**：无原生 Hook 时，用 `project-skeleton/hooks/` 下的脚本承载可确定性执行的部分（记忆写入、缺口报告、CI 门禁通知、假象检测），模型在各阶段/任务边界显式调用脚本。
3. **模型显式执行兜底**：脚本/平台均不可用时，模型在对应节点**显式执行**固定动作，**不得静默跳过**——这是最低要求，违反即门控不通过。

## 与既有机制的关系

- `on-irreversible-action` 与「第五章自由度档位」中**低自由度步骤**强绑定：低自由度步骤触发本 Hook，强制人工确认。
- `on-gate-fail` 与「第六章仲裁环」联动：门控失败即仲裁环介入；`on-task-complete` 检测到假象时也联动本 Hook。
- `on-task-complete` 与阶段6 **反指标环**互补：前者是任务粒度的事前/事中检查，后者是阶段粒度的事后审计。
- 所有 Hook 的执行结果都写入 `.6a-memory/session/`，可被 `scripts/memory-audit.sh` 校验是否遗漏。
