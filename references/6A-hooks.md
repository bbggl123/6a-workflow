# 生命周期 Hook（v4.2 新增）

> 本文件是 6A 权威协议的分章加载单元。理解阶段切换与自动动作触发时加载；脚本化版本见 `project-skeleton/hooks/`。

> 课程原则：Hook 在开始、完成、失败等节点**自动触发固定动作**（如代码审查完发通知），不依赖模型每步自觉执行。6A 定义四类触发点：

| Hook | 触发时机 | 固定动作 | 降级（平台不支持 Hook） |
|---|---|---|---|
| `on-phase-enter` | 进入某阶段时 | 写记忆 `[CHECKPOINT] 进入阶段X` + 更新 `progress/current-phase.md` | 模型显式执行（不静默跳过），阶段开头第一句即写 |
| `on-phase-exit` | 阶段质量门控通过时 | 写 `[CHECKPOINT] 阶段X 完成` + 更新 `completed.md` + 通知（如发评论/消息） | 模型显式执行 + 主动向用户同步阶段完成 |
| `on-gate-fail` | 门控不过时 | 记录失败原因到 `blockers.md` + 记录 `[ERROR]` + 循环回退起点 | 模型显式记录原因后再回退，不得静默重做 |
| `on-irreversible-action` | 删除 / 迁移 / 部署 / 强推前 | 要求人工确认（与阶段4 三级制联动）+ 记录 `[APPROVE]` | 模型显式停下向用户确认，确认后才执行 |

## 实现形态

1. **平台原生 Hook**：若运行平台支持生命周期回调，优先用平台 Hook 注册上述四类触发点的固定动作。
2. **脚本化降级**：无原生 Hook 时，用 `project-skeleton/hooks/` 下的脚本承载可确定性执行的部分（记忆写入、缺口报告、CI 门禁通知），模型在各阶段边界显式调用脚本。
3. **模型显式执行兜底**：脚本/平台均不可用时，模型在对应节点**显式执行**固定动作，**不得静默跳过**——这是最低要求，违反即门控不通过。

## 与既有机制的关系

- `on-irreversible-action` 与「第五章自由度档位」中**低自由度步骤**强绑定：低自由度步骤触发本 Hook，强制人工确认。
- `on-gate-fail` 与「第六章仲裁环」联动：门控失败即仲裁环介入。
- 所有 Hook 的执行结果都写入 `.6a-memory/session/`，可被 `scripts/memory-audit.sh` 校验是否遗漏。
