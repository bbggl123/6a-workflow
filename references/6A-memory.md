# 7.9：项目级记忆系统（Context Persistence · v4 全新核心）

> 本文件是 6A 权威协议的分章加载单元。standard/complex 任务部署记忆系统时加载；trivial 任务跳过。

> **问题背景**：LLM 上下文窗口有限，长任务中极易"失忆"——忘记之前的决策、已读过的文件、已确认的约定。6A v4 引入**项目级持久化记忆系统**，在工作流激活的瞬间即部署，每操作一步同步一步，从根本上解决上下文溢出导致的失忆问题。

## 7.9.1 记忆系统部署时机

**6A 激活后第一件事（阶段1 步骤0）**：在项目根目录创建 `.6a-memory/` 目录结构。该目录应加入 `.gitignore`（本地工作记忆，不入库），但记忆格式本身是纯文本 Markdown，可人工审阅、可版本化、可跨会话恢复。

> 如果项目中已存在 `.6a-memory/`，说明是续接任务——**先读取 INDEX.md 和最近的记忆文件恢复上下文，再开始工作**，禁止假设"什么都不记得"。

## 7.9.2 记忆目录结构

```
.6a-memory/
├─ INDEX.md              # 记忆总索引（每次操作更新最后修改时间）
├─ session/
│   └─ YYYY-MM-DD-HHMMSS.md  # 当前会话日志（按启动时间命名）
├─ context/
│   ├── project.md       # 项目画像：技术栈、架构模式、目录结构、命名规范
│   ├── codebase.md      # 代码库索引：关键文件、核心模块、已有组件、依赖
│   └── domain.md        # 业务领域：核心数据模型、业务规则、术语表
├─ decisions/
│   └─ DECS-001.md ~ DECS-NNN.md  # 决策日志（每做一个关键决策即记录）
├─ progress/
│   ├── current-phase.md # 当前所处阶段、角色、正在执行的任务
│   ├── completed.md     # 已完成任务清单（含验收证据）
│   └─ blockers.md       # 阻塞项、待人工确认的问题
└─ lessons/
    └─ learned.md        # 本次任务新发现的坑、有效技巧、可复用经验
```

## 7.9.3 记忆条目格式（强制规范）

每条记忆必须包含以下字段，写入对应文件时使用统一模板：

```markdown
<!-- 记忆条目模板 -->
### [动作类型] 简短摘要
- **时间**: `YYYY-MM-DD HH:MM:SS (UTC+8)`
- **阶段**: Align / Architect / Atomize / Approve / Automate / Assess
- **角色**: 规划 / 执行 / 评估 / 守门员
- **相关文件**: `path/to/file1`, `path/to/file2`
- **详情**:
  （具体做了什么、发现了什么、决定了什么）
- **可信度**: XX%（如涉及结论/决策）
```

**动作类型枚举**：
- `[READ]` 读取了某个文件/资料
- `[DECIDE]` 做出了某个设计/选型决策
- `[MODIFY]` 修改/创建了某个文件
- `[RUN]` 运行了某个命令（测试/构建/脚本）
- `[FIND]` 发现了某个问题/事实
- `[ASK]` 向用户提出了问题
- `[APPROVE]` 用户确认/审批了某个事项
- `[ERROR]` 遇到了错误/阻塞
- `[CHECKPOINT]` 阶段完成/质量门控通过

## 7.9.4 "每操作一步同步一步"执行纪律

1. **先写记忆，再做下一步**（Write-ahead Memory Logging）：
   - 读取重要文件 → 立即在 `session/` 记录 `[READ]`
   - 做出关键决策 → 立即在 `decisions/` 创建 DECS 条目，在 `session/` 记录 `[DECIDE]`
   - 修改/创建文件 → 立即记录 `[MODIFY]`，摘要说明改动
   - 运行命令 → 记录 `[RUN]`，记录命令和关键结果（成功/失败）
   - 遇到问题 → 立即记录 `[ERROR]`，记录错误现象和初步判断
   - 用户确认 → 记录 `[APPROVE]`，记录确认内容
   - 阶段完成/门控通过 → 记录 `[CHECKPOINT]`，更新 `current-phase.md`

2. **上下文恢复规则**：
   - 每次感觉"不确定之前做了什么"时，**不要猜**，先读 `.6a-memory/progress/current-phase.md` 和最近的 session 日志
   - 续接任务时，读取顺序：INDEX.md → current-phase.md → 最近 session → decisions（按编号倒序读最近5条）
   - 代码修改前，检查 `context/codebase.md` 是否已有该模块的记录，避免重复读取/重复造轮子

3. **记忆完整性自检（守门员执行）**：
   - 每个阶段质量门控新增一项检查：`.6a-memory/` 中该阶段的记忆条目是否完整
   - 关键操作（决策、文件修改、用户审批）无对应记忆记录 → 阶段门控不通过
   - session 日志时间戳必须连续，出现超过10分钟无记录的间隙时，守门员需提醒补记
   - 记忆完整性可由确定性脚本自检：`scripts/memory-audit.sh` 扫 `.6a-memory/` 时间戳连续性，输出缺口报告；守门员据脚本结果判断，模型纪律降为兜底。

## 7.9.5 记忆隐私与安全

- `.6a-memory/` 默认加入 `.gitignore`（本地工作记忆）
- 记忆文件中**禁止记录**：API密钥、密码、个人隐私数据（参考 opus-5 隐私规范）
- 决策记录（DECS-*）中若涉及敏感信息，使用占位符替代并标注 `[REDACTED]`
- 任务结束后，`lessons/learned.md` 中可复用的经验应沉淀到项目 `knowledge/` 红线库（持久化保留）
